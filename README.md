# Фронтенд-задание

Разработайте небольшое фуллстек-приложение — справочник пользователей. Цель — оценить, как вы проектируете интерфейс с поиском, фильтрацией и пагинацией, опирающийся на сохранённые данные и чёткие границы API.

Приложение должно включать:

- React-клиент.
- API-сервер на Node.js.
- Базу данных SQLite в качестве источника истины для данных о пользователях.
- Конфигурацию Docker для локального запуска приложения.

## Использование ИИ-ассистентов

Использование инструментов разработки с ИИ (Claude Code, Codex и подобных) разрешается и даже требуется. При этом необходимо хорошо ориентироваться в итоговом коде: на разборе может потребоваться внести небольшие правки вручную.

## Сценарий

Пользователям нужно просматривать большой справочник людей, искать по имени и фильтровать результаты по национальности и хобби. Боковая панель фильтров должна помогать пользователям подбирать полезные фильтры на основе текущего набора отображаемых результатов.

## Требования

### Модель данных

Наполните базу данных SQLite достаточным количеством записей, чтобы пагинация, бесконечная прокрутка, поиск и счётчики фильтров имели смысл.

У каждого пользователя должны быть:

- `avatar`
- `first_name`
- `last_name`
- `age`
- `nationality`
- `hobbies` — от 0 до 10 хобби на пользователя

Выберите модель данных, которая поддерживает требуемое поведение.

SQLite должна быть постоянным источником данных о пользователях.

### API

Реализуйте API, который поддерживает:

- Постраничную выдачу пользователей.
- Текстовую фильтрацию по вводу пользователя по полям `first_name` и `last_name`.
- Фильтрацию по одной или нескольким национальностям.
- Фильтрацию по одному или нескольким хобби.
- Сортировку по `first_name`, `last_name`, `age` и `nationality`.
- Метаданные пагинации, чтобы клиент мог определить, доступны ли ещё результаты.
- Топ-20 хобби для текущего текстового фильтра и состояния фильтров, включая `{ value, count }`.
- Топ-20 национальностей для текущего текстового фильтра и состояния фильтров, включая `{ value, count }`.

Топ-20 значений и счётчики должны отражать текущий применённый текстовый фильтр и выбранные фильтры, а не весь набор данных.

Семантика фильтрации:

- Несколько выбранных хобби должны соответствовать пользователям, у которых есть все выбранные хобби.
- Несколько выбранных национальностей должны соответствовать пользователям из любой выбранной национальности.
- Текстовый фильтр, фильтр по хобби и фильтр по национальности должны применяться совместно.

Семантика сортировки:

- Отсортированные результаты должны быть детерминированными. Используйте `id` как окончательный критерий при равных значениях.
- Пагинация должна учитывать активную сортировку без дублирования или пропуска пользователей.

### Клиент

Разработайте интерфейс на React, который включает:

- Поле текстового фильтра по `first_name` и `last_name`.
- Виртуализированный список карточек пользователей с бесконечной прокруткой.
- Боковую панель с топ-20 хобби и топ-20 национальностей для текущего набора результатов, включая счётчики.
- Элементы управления для применения и снятия фильтров по хобби и национальности.
- Элементы управления для выбора поля и направления сортировки.
- Состояния загрузки, пустого результата и ошибки.
- Адаптивную вёрстку, которая остаётся удобной на десктопе и на мобильных устройствах.

Карточки пользователей должны иметь следующую структуру:

```text
|----------------------------------|
| avatar      first_name+last_name |
|             nationality      age |
|                                  |
|             (2 hobbies) (+n)     |
|----------------------------------|
```

Показывайте на карточке не более 2 хобби. Если у пользователя больше хобби, отображайте количество оставшихся как `+n`.

Используйте для списка реализацию виртуальной прокрутки.

При изменении текстового фильтра или выбранных фильтров клиент должен обновлять одновременно:

- Постраничный список пользователей.
- Топ-20 хобби и национальностей в боковой панели.

Значение текстового фильтра, выбранные хобби, выбранные национальности, поле сортировки и направление сортировки должны отражаться в строке запроса URL. Перезагрузка или передача URL должны восстанавливать то же состояние отображения.

## Замечания по реализации

- Сделайте настройку базы данных простой для локального запуска.
- Включите логику наполнения данными или задокументированную команду, которая создаёт базу данных SQLite.
- Включите `Dockerfile` и `docker-compose.yml`, которые позволяют запускать приложение локально.

## На что обращаем внимание при оценке

Особое внимание мы уделим следующему:

- Корректное сохранение данных и поведение API.
- Корректные фильтрация, сортировка, пагинация и счётчики топ-20.
- Плавная бесконечная прокрутка с виртуализацией.
- Состояние, синхронизированное с URL.
- Понятные состояния загрузки, пустого результата и ошибки.
- Простая настройка как локально, так и через Docker.
